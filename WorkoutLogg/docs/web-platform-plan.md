# Веб-платформа для фитнес-залов

## Согласованные требования

- React-веб-приложение с функциями текущего клиента.
- Отдельный домен и отдельный вход для каждого зала.
- Админка зала: главная, профиль, тренеры и оформление бренда.
- Существующие MAUI-клиенты сохраняются на время переноса.

## Архитектура

Один React + TypeScript клиент и один ASP.NET Core API обслуживают все залы.
Домен сопоставляется с зарегистрированной организацией на сервере. Неизвестный
домен не получает доступ к организации по умолчанию. Переключения организации
через произвольный tenant-id от клиента нет.

По решению владельца проекта используется **одна PostgreSQL БД и отдельная
схема на зал**, например `gym_atlas`, `gym_pulse`. Все модульные таблицы зала
находятся в его схеме. Старое приложение временно использует организацию
`legacy` и существующие схемы `users`, `trainers`, `subscriptions`: переносить
или удалять существующие данные автоматически нельзя.

Доменный каталог задаёт разрешённые домены, схему и ID владельцев. EF Core
строит отдельную модель для каждой схемы. Миграции модулей сохраняют исходные
snapshot-модели, а специальный Npgsql SQL generator перенаправляет структурные
операции в схему зала. История миграций каждого модуля отдельная. Redis, JWT,
сброс пароля, фоновые письма и live-события также учитывают организацию.

Вход, сброс пароля и сессии ограничены доменом. Один email может использоваться
в разных залах как разные аккаунты. Права владельца/администратора нельзя
назначать из формы регистрации. Первое назначение владельца выполняет оператор
платформы; дальнейшее управление доступами — через админку.

## Настройка бренда

Проверяемая конфигурация: название, логотип, основной/акцентный цвет, светлая и
тёмная палитры, скругления, плотность интерфейса. Главная и профиль собираются из
готовых блоков (приветствие, объявления, статистика, тренеры, расписание, ссылки).
Администратор меняет содержимое, видимость и порядок; произвольные JS/CSS/HTML
не исполняются. Изменения сохраняются как черновик и публикуются явно.

## Карта переноса

| Область | Сейчас | Что требуется в вебе |
|---|---|---|
| Вход, регистрация, восстановление | REST | Браузерная сессия и формы |
| Профиль, цели, параметры тела | REST + MAUI | Формы и серверная валидация |
| Шаблоны, упражнения, подходы | SQLite + REST/gRPC | Полный REST-контракт и редактор |
| Журнал тренировок | Локальная SQLite | Серверное хранение и синхронизация |
| Главная, рекорды, достижения | Вычисления MAUI | Перенос вычислений и настраиваемые блоки |
| AI-коуч | REST | Чат и лимиты |
| Тренеры и фильтры | REST | Каталог, карточка, управление администратором |
| Заявки, расписание, бронирования | REST | Клиентские и тренерские экраны |
| Сообщения | REST polling | Список диалогов и чат |
| Кошелёк и подписки | REST | История, бонусы, оплата, возврат из браузера |
| Нормативы, справочные страницы | MAUI | Веб-страницы |
| Организации, роли, контент, бренд | Нет | Новый серверный модуль и админка |

## Порядок работ и критерии приёмки

1. Доменная изоляция, серверные права и тесты доступа между двумя залами.
2. React-каркас, вход, профиль, единая дизайн-система и темы.
3. Админка бренда, блоков главной/профиля и тренеров с публикацией.
4. Перенос дневника с локальной модели на API, затем остальных разделов по карте.
5. Интеграционные проверки, адаптивность, миграция данных MAUI и эксплуатация.

Полный перенос нельзя считать завершённым по наличию экранов: каждое действие
должно работать с реальным API, а данные залов A/B не должны пересекаться при
подмене домена, токена, идентификатора записи или ключа кеша.

## Реализовано в первой версии

- React + TypeScript + Vite: вход, регистрация, восстановление пароля; HttpOnly
  сессия, access token только в памяти, восстановление после перезагрузки.
- Главная, тренировки с упражнениями и подходами, профиль и темы, каталог
  тренеров, заявки, бронирования, сообщения и кошелёк с бонусами.
- Кабинет тренера: заявки, расписание и статусы занятий; AI-коуч и справочные
  таблицы; просмотр и восстановление подписки.
- Админка: название, акцентный цвет, тема по умолчанию, форма элементов,
  текстовые блоки главной/профиля, порядок и видимость, черновик/публикация.
- Назначение карточек тренера существующим участникам. Первого владельца
  назначает оператор по ID, а не по самостоятельно введённому email.
- Тесты схем, миграций, JWT, кеша сброса пароля и live-событий.

Полный паритет с MAUI ещё требует переноса локальных шаблонов/журнала SQLite
и синхронизации старых данных, оставшихся расширенных функций тренера
(верификация, отзывы, платежи), полноценного браузерного checkout и настройки
платёжных интеграций каждого зала. Загрузка логотипов и произвольные композиции
страниц пока не реализованы; доступные блоки — текстовые объявления.

Запуск, домены и эксплуатационные ограничения описаны в [web-platform.md](web-platform.md).

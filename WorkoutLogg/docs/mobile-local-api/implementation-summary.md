# Результат

Ветка `main`; изменения предыдущих задач сохранены.

Подтверждены неправильный выбор адреса эмулятора для телефона и отсутствие восстановления формы при исключениях запросов.

## Изменения

- `WorkoutLogg/MauiProgram.cs`: адрес `LocalAndroidUrl` применяется только к Android-эмулятору (`DeviceType.Virtual`). Телефон использует `LocalUrl` через USB-проброс. Локальный gRPC использует тот же HTTPS endpoint с поддержкой HTTP/2.
- Для `IAuthApi` и `IAuthRefreshApi` установлен тайм-аут HttpClient 30 секунд на запрос.
- `CreateAccount.xaml.cs` и `LoginPage.xaml.cs`: добавлены защита от повторной отправки, обработка сетевых исключений / тайм-аутов, восстановление исходной формы при ошибках. После неуспешного получения CurrentUser или неизвестного шага регистрации показывается ошибка вместо бесконечной загрузки.
- Сообщения добавлены в русскую и английскую локализации.
- Настроен ADB reverse портов 5001 и 5000 на подключённом физическом телефоне.
- README описывает порядок запуска и отличие адреса эмулятора от USB-телефона.

## Проверки

- Android ARM64 Debug: сборка успешна, 0 ошибок, 212 предупреждений. Использован установленный JDK 21, восстановленные ранее зависимости.
- `adb reverse --list`: подтверждены оба проброса.
- Проверочный запуск локального API: HTTPS `/alive` с компьютера ответил `Healthy`, HTTP 200. Проверка curl выполнялась с `-k`, без проверки доверия сертификату.
- HTTP-запрос из Android shell через `localhost:5000` дошёл до Kestrel и получил HTTP 307 с `Location: https://localhost:5001/alive`.
- Первые попытки проверки через Android `nc` завершались без ответа из-за раннего EOF stdin; повтор с удержанием входного потока подтвердил маршрут. Это особенность диагностической команды, не мобильного HttpClient.

## Состояние после проверки и ограничения

- Проверочные процессы API остановлены; API необходимо запустить в IDE вместе с клиентом. Пробросы ADB оставлены включёнными.
- Обновлённый APK собран, но не установлен на телефон в рамках задачи. Нужен повторный запуск клиента из IDE.
- Полный HTTPS-запрос из обновлённого мобильного интерфейса, взаимодействие с контроллерами авторизации, восстановление UI при тайм-ауте и gRPC на устройстве не проверялись. Проверены сборка, маршрут телефон → HTTP Kestrel и HTTPS API с компьютера.
- Сценарии подключения по Wi-Fi и Release с доверенным сертификатом не менялись и не проверялись.

## Повторная диагностика ConnectException

- Пользователь предоставил `Java.Net.ConnectException: Failed to connect to localhost/127.0.0.1:5001` после запуска обновлённого клиента.
- На момент повторной проверки API уже работал из IDE: порт 5001 слушался, HTTPS `/alive` с компьютера возвращал `Healthy`, HTTP 200.
- Список `adb reverse --list` у физического телефона оказался пуст. Ранее настроенные пробросы не сохранились в текущем подключении.
- Повторно выполнены `adb -d reverse tcp:5001 tcp:5001` и `adb -d reverse tcp:5000 tcp:5000`; оба проброса подтверждены списком.
- Повторный HTTP-запрос из Android shell получил HTTP 307 от Kestrel с перенаправлением на HTTPS 5001; API с компьютера продолжил отвечать `Healthy`.
- Запущенный пользователем API оставлен работающим. Для повторения мобильного запроса после восстановления проброса пересборка приложения не требуется.
- `git diff --check` прошёл после изменений кода и документации. Полный запрос авторизации из мобильного UI пользователю нужно повторить.

Модульная память отсутствует в целевом репозитории и не обновлялась. Долгоживущие правила локального подключения сохранены в README.

# Результат: XARDF7024 при сборке Android-клиента

Ветка: `main`. Изменения предыдущей задачи по локальному API и пользовательские изменения сохранены.

## Причина и исправление

- У пустого каталога `WorkoutLogg/obj/Debug/net10.0-android/android-arm64/stamp` обнаружены атрибуты `ReadOnly, Directory, Archive`.
- ACL разрешал изменение. Наличие ReadOnly препятствовало удалению каталога задачей `RemoveDirFixed`.
- Через `attrib.exe -R` снят ReadOnly с `WorkoutLogg/obj`, `WorkoutLogg/bin` и их содержимого, включая вложенные каталоги (`/S /D`).
- После исправления у `stamp` остались атрибуты `Directory, Archive`.
- Исходный код клиента, права ACL и процессы IDE не изменялись. Удаление сгенерированных каталогов не потребовалось.

## Проверки

- Сборка `dotnet build WorkoutLogg/WorkoutLogg.csproj -f net10.0-android -r android-arm64` с явным `JavaSdkDirectory`, взятым из пользовательского `JAVA_HOME`: успешно, 0 ошибок, 215 предупреждений, около 45 секунд.
- Создан `WorkoutLogg/bin/Debug/net10.0-android/android-arm64/com.companyname.workoutlogg-Signed.apk`.
- Ошибка XARDF7024 не воспроизвелась. Других блокирующих ошибок окружения в этой сборке не было.
- Обновлена инструкция диагностики ReadOnly в README.

## Ограничения

- Установка APK и запуск на телефоне в этой задаче не выполнялись.
- Предупреждения сборки не исправлялись.
- Источник установки атрибута ReadOnly не установлен; копирование промежуточных каталогов при переносе проекта могло сохранить этот атрибут, но это не подтверждено.
- Модульная память в целевом репозитории отсутствует и не обновлялась; подтверждённый способ диагностики и восстановления описан в README.

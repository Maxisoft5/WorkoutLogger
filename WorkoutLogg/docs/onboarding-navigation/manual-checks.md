# Ручная проверка на Samsung A51

Пользователь выбрал самостоятельную проверку на телефоне. Этот список описывает
ожидаемое поведение, а не результаты уже выполненного UI-теста.

## Переносы текста

Проверить русский и английский языки. На A51 исходный масштаб шрифта — 1.1;
дополнительно полезно проверить увеличенный шрифт и узкий экран около 320 dp.

1. CreateAccount: соглашение полностью видно, обе ссылки нажимаются; подпись
   «Уже есть аккаунт?» переносится вместе со ссылкой без горизонтального обрезания.
2. Login: подпись регистрации под кнопкой входа переносится, ссылка нажимается.
3. OnboardingProfile: заголовок, описание и обе кнопки пола полностью читаются;
   длинная подпись кнопки увеличивает высоту строки.
4. OnboardingBodyStats: текст подсказки с иконкой переносится внутри карточки;
   кнопки «Назад» / «Продолжить» читаются при увеличенном шрифте.
5. OnboardingGoals: заголовки и описания всех шести целей полностью читаются;
   высота карточки подстраивается под текст; отметка выбора остаётся справа.
6. Частота тренировок: все шесть вариантов видны в сетке 3×2. Кнопка завершения
   доступна, содержимое страницы прокручивается.

## Навигация и загрузка

1. Пересобрать и запустить обновлённый клиент. Сохранить доступность API и USB reverse,
   чтобы сетевую ошибку не принять за медленную отрисовку.
2. Пройти Dashboard → Workouts → Logger → AI → Profile → Dashboard.
3. При первом нажатии на новую вкладку оверлей должен появляться ещё на исходной
   странице. На целевой странице загрузка продолжается до готовности её данных.
4. Повторить круг: календарь должен использовать существующие ячейки, а не создавать
   их заново при каждом обновлении меток.
5. Быстро нажать две разные вкладки: во время первого перехода второй не должен
   создавать параллельную Shell-навигацию.
6. Проверить переходы из Profile в Premium / Standards / Trainers / Wallet и возврат
   назад; после возврата оверлей должен скрываться по завершении загрузки.
7. В Workouts / Logger проверить прокрутку календаря вместе со списком, фильтры,
   выбор дат, пустой список и длинную историю. Метки календаря должны сохраняться.
8. Перевести приложение в фон во время перехода и вернуться: ожидание кадра имеет
   ограничение 250 мс, постоянный оверлей из-за ожидания callback недопустим.

## Замеры

В Debug-выводе IDE искать:

```text
[Navigation] //Workouts: feedback ... ms
[Navigation] //Workouts: Shell transition ... ms (including feedback; excludes async data loading)
[PageLoad] Workouts: ... ms
```

- `feedback` — время подготовки индикатора и ожидания кадра перед GoToAsync.
  Это диагностическая граница, а не аппаратный замер появления пикселей на дисплее.
- `Shell transition` — время от запроса перехода до завершения GoToAsync, включая
  подготовку индикатора. Async-загрузка страницы может продолжаться отдельно.
- `PageLoad` — время обработчика OnAppearing, включая подготовку кадра и загрузку
  данных; оно не включает всю последующую отрисовку списка платформой.

Записывать первый и повторный переход отдельно. Для оценки пользовательской
скорости дополнительно проверить Release без подключённого отладчика: Debug,
Hot Reload и JIT могут заметно менять результаты. Целевые значения на A51 пока
не подтверждены измерениями.
